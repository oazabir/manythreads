Rate limits and lockouts on sign-in and other credential routes (full table: docs/deploy/rate-limits.md)
-------------------------------------------------------------------------------------------------------
Over a limit the server answers 429 rate_limited with a retry-after header.
PER REPLICA: every counter and every lock lives in the memory of one server process, never in the database. With N server
replicas each one counts alone (the effective limit is N times the number below), and a restart clears them all.
The client address is taken from X-Forwarded-For only for {{ .Values.server.trustProxy }} proxy hop(s) (server.trustProxy;
MANYTHREADS_TRUST_PROXY){{ if eq (toString .Values.tls.mode) "cloudflare" }}, plus one for Cloudflare{{ end }}: set it to the number of proxies in front of
the server pod, or every visitor shares one counter. On k3s the Traefik Service must keep the visitor's address (externalTrafficPolicy:
Local) unless Cloudflare is in front: then the chart also reads CF-Connecting-IP (MANYTHREADS_CLIENT_IP_HEADER) and the origin must accept Cloudflare only. Keep the server Service unreachable from untrusted pods: a caller that
skips the proxies can choose its own address.

Per client address, per 60 seconds:
  sign-in 30 | password reset request 5 | password reset 5 | email verification 10 | first-admin setup link 10 check, 5 submit
  invitation lookup 10 | invitation accept 10 | single sign-on (OIDC) start 30 | OIDC callback 30 | runner socket 60
  webhook calls /hooks 600 | bot pairing mint /api/mcp/runs 60
  wrong bot or run tokens (/mcp, /api/mcp/bots, /api/llm/runs) 60 failures a minute, then 429
Per signed-in person, per 60 seconds:
  change password 5 | email verification request 5 | sign out 30 | sign out everywhere 10 | list sessions 60 | revoke a session 30
  team and workspace invitation create 30 | bot pairing token mint 10 / rotate 10 / revoke 30 | runner token mint 30 | webhook create / rotate / revoke 30 | app token 120
Lockouts (temporary, in memory): 5 wrong passwords for one email from one address lock that pair 15 minutes; 25 for one email from
any address lock the account 15 minutes (a completed password reset lifts it); 5 wrong current passwords lock a password change
15 minutes; 10 refused reset, verification, setup or invitation links from one address lock that address 15 minutes; 30 calls to
/hooks with no live webhook or a wrong secret lock the address 5 minutes for failing calls (a right secret still posts).

The database: failover and restore (docs/deploy/backup.md)
----------------------------------------------------------
{{- if eq .Values.postgres.mode "cnpg" }}
Postgres runs under CloudNativePG ({{ .Values.postgres.instances }} instance{{ if ne (int .Values.postgres.instances) 1 }}s{{ end }}). {{ if gt (int .Values.postgres.instances) 1 }}If the primary fails, a standby takes over within about a minute and the Service manythreads-pg-rw follows it.{{ else }}With one instance there is no standby: a failed pod is restarted, and the site is down until it is back. Set postgres.instances to 3 for a standby that takes over.{{ end }}
UNLOGGED tables (a table made UNLOGGED is not written to the write-ahead log) are EMPTY after a failover or a crash, and they are not on a standby. The platform keeps nothing
it cannot lose in one; if you add a table of your own, do not make it UNLOGGED unless it can be rebuilt.
{{- else }}
Postgres runs as a single StatefulSet (postgres.mode=statefulset): no standby, no failover. Use postgres.mode=cnpg for both.
{{- end }}

Restore from the nightly dump (the default; templates/backup.yaml, backup.enabled):
  bash tools/backup/restore.sh --help        # restores a set into a namespace after you type its name; tools/backup/drill.sh proves the latest set restores
{{- if .Values.postgres.objectStore.enabled }}

Continuous backup to object storage is ON (postgres.objectStore: bucket {{ .Values.postgres.objectStore.bucket }}, base backup {{ .Values.postgres.objectStore.schedule }}, kept {{ .Values.postgres.objectStore.retention }}).
It needs the CloudNativePG Barman Cloud plug-in installed in the cluster ({{ .Values.networkPolicies.release.operatorNamespace }} namespace); this chart does not install it and its objects were NOT tried on a cluster that has it.
Restore to a point in time: make a NEW Cluster (another name) that recovers from the store, check it, then point the platform at it:
  apiVersion: postgresql.cnpg.io/v1
  kind: Cluster
  metadata: { name: manythreads-pg-restored }
  spec:
    instances: 1
    storage: { size: {{ .Values.postgres.storage.size }} }
    bootstrap:
      recovery:
        source: origin
        recoveryTarget: { targetTime: "2026-01-31 12:00:00+00" }   # leave out for "the latest"
    externalClusters:
      - name: origin
        plugin:
          name: barman-cloud.cloudnative-pg.io
          parameters: { barmanObjectName: manythreads-pg-store, serverName: manythreads-pg }
Stop the server first (kubectl scale deployment manythreads-server --replicas=0), and keep the blobs and repositories volumes: they are not in the database backup.
{{- else }}

Continuous backup (point-in-time restore) is OFF: the nightly dump is the only database backup, so up to a day of changes can be lost. To turn it on, install the CloudNativePG
Barman Cloud plug-in and set postgres.objectStore (bucket, existingSecret with the keys access-key and secret-key).
{{- end }}
{{- if .Values.networkPolicies.release.enabled }}

Network policies of this namespace: the database takes calls only from the platform's own workloads, Hindsight only from the server, LiteLLM only from the server, Hindsight and the
Hermes pods' namespace. A tool you run in this namespace that must reach one of them needs the label app.kubernetes.io/component=backup-tool (what tools/backup uses) or its own policy.
Roll back with networkPolicies.release.enabled=false.
{{- end }}
